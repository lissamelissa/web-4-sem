# Восстановление проекта Planify

Это все файлы, которые пересылались в чате по ходу разработки, собранные в одну
структуру. Они воссоздают состояние проекта на момент "всё работает":
главная страница с виджетами, календарь, таблицы задач/финансов, избранное,
доп. библиотеки в админке, доступность, печать.

## Как применить

1. **Сделайте резервную копию** текущей папки `web4sem` на всякий случай
   (просто скопируйте её целиком куда-нибудь ещё) — на случай, если что-то
   в вашей текущей версии окажется новее того, что здесь.

2. Скопируйте содержимое этого архива **поверх** вашего проекта — то есть
   папку `planify/` и `plapp/` из архива кладите поверх одноимённых папок
   в `web4sem/`, подтверждая замену файлов. `requirements.txt` и
   `.gitignore` — в корень проекта.

   Важно: `planify/settings.py` и `planify/urls.py` в архиве — это ПОЛНЫЕ
   файлы, они заменяют ваши целиком. Если вы что-то своё туда дописывали
   отдельно от того, что обсуждали в чате — перенесите это вручную перед
   заменой.

3. Установите зависимости и накатите миграции:

   ```bash
   pip install -r requirements.txt
   python manage.py makemigrations
   python manage.py migrate
   ```

4. Если БД сейчас пустая или в ней мало записей — снова наполните её:

   ```bash
   python manage.py seed_demo_data
   ```

5. Запустите сервер и проверьте, что всё вернулось:

   ```bash
   python manage.py runserver
   ```

   Откройте `http://127.0.0.1:8000/home/1/` (или id любого пользователя) —
   должна открыться главная страница с виджетами.

## Самое важное — сразу закоммитьте

Именно отсутствие коммита стало причиной вчерашней потери кода. Как только
убедитесь, что сайт работает:

```bash
git add .
git commit -m "Restore full project: home page, calendar, tables, admin extras"
git push
```

Не открывайте эксперименты с `git checkout`/`git reset --hard` на других
ветках, пока это не закоммичено — если что-то не закоммичено, оно живёт
только в рабочей папке и пропадает при переключении веток.

## Что НЕ входит в архив (и не должно)

- `db.sqlite3` — у вас своя локальная база, архив её не трогает.
- `media/` — загруженные файлы (изображения задач, чеки) — они у вас уже есть.
- `plapp/migrations/` — Django сгенерирует их сам командой `makemigrations`
  на основе `models.py` из архива.
- Отчёты `.docx` по лабораторным — они не часть кода проекта, оставлены
  отдельно в чате.
